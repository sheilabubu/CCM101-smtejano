# Mission Reflection: Cloud Automation Engineer

Cloud automation is important when managing hundreds of cloud servers because it saves time, reduces repetitive manual work, and helps prevent human errors. Instead of running the same commands on every server, administrators can use scripts and scheduled tasks to perform operations consistently. For example, the Bash backup script I created can automatically compress application data, while Cron can schedule it to run every day at 2:00 AM. Automation also has potential dangers. A small mistake in a script can cause serious problems if it runs on many servers. For example, a destructive command or an incorrect file path could accidentally delete important data across 1,000 servers. This is why scripts should be reviewed, tested in a safe environment, and provided with appropriate permissions before being deployed widely. Backups and monitoring are also important for recovering from unexpected problems. Writing a Bash script in Laboratory 9 was different from creating a Docker Compose YAML file in Mission 6. Bash scripting focuses on executing commands and performing tasks step by step, such as creating folders and compressing files. Docker Compose YAML, on the other hand, describes how containers and services should be configured and connected. Both are useful automation tools, but they serve different purposes. From Laboratory 1 to Laboratory 9, my understanding of cloud computing has grown from learning basic infrastructure and Linux commands to understanding virtualization, containers, cloud operations, security, and automation. I learned that cloud computing involves more than hosting applications because it also requires managing resources, protecting data, monitoring systems, and maintaining reliable services. The role I enjoyed the most was Cloud Automation Engineer because I liked learning how to make repetitive tasks run automatically. Creating and testing a backup script helped me understand how automation can make system administration more efficient. Overall, this mission taught me that cloud engineers must not only know how to configure systems but also how to automate them carefully, test their work, and take responsibility for the results.
