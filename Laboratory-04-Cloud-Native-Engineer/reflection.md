# Mission Reflection

This laboratory gave me a better idea of how Docker containers are used when deploying applications. I learned that containers are generally lighter and faster to start than Virtual Machines, with a VM, I need to allocate resources and run a complete operating system before using the application. Docker containers only contain what is needed for the application, so they can be started and deployed more quickly. I also learned the purpose of the port mapping `-p 8080:80`. The Nginx server uses port 80 inside the container, but I can access it through port 8080 on the host computer. Because of this connection, I can open `http://localhost:8080` and see the Nginx web server running inside the container. This helped me understand how applications inside containers can be accessed from outside. Another thing I learned was that removing a container with `docker rm` also removes the container itself and any data that was stored only inside it. This showed me why persistent storage is important when an application needs to keep its data. Docker volumes can be used when files or other information need to remain available even after a container is removed. Docker can also make teamwork between developers and IT operations easier. Developers can prepare an application together with its dependencies inside a container, and the operations team can use the same container when deploying it. This can help avoid problems caused by differences between development and production environments. This laboratory added a new skill to my GitHub portfolio, I mainly worked with basic cloud and Linux concepts. After finishing this laboratory I gained practical experience with Docker, containers, Nginx, port mapping, and container management. It helped me understand how containerization is used in modern cloud-native environments.
