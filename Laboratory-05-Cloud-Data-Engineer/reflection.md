# Mission Reflection

This laboratory helped me understand how object storage works and why it is useful for handling a large number of files. I learned that object storage is suitable for storing millions of photos because it is designed to manage large amounts of unstructured data. Each file is stored as an object with its own identifier and metadata, making the files easier to organize and access as the amount of data grows. Using Docker also helped me understand how MinIO can be deployed more easily. Instead of manually installing and configuring the storage server, I was able to use a Docker command to create the MinIO container and set the required ports and credentials. This made the deployment process simpler and showed me how containers can be useful for setting up applications. I learned that a bucket is a storage container where objects such as photos, documents, and other files are kept. In this laboratory, I created the `client-photos` bucket and uploaded a sample file to confirm that the MinIO storage system was working correctly. I also learned that large companies need different ways to protect their stored data from being lost. They can use backups, replication, redundancy, and multiple storage locations to keep additional copies of important files. If one server or storage location fails, another copy can be used to recover the data. This laboratory also helped improve my confidence in using the Linux command line. At first, I was still unfamiliar with some Docker commands and their options. By practicing commands such as `docker pull`, `docker run`, and `docker ps`, I became more comfortable using them. I also learned to check my command syntax carefully because small mistakes can cause errors. Overall, this laboratory gave me more practical experience with Linux, Docker, MinIO, and object storage.
