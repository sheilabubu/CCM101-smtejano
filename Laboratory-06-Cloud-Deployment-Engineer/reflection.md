# Mission Reflection

This laboratory helped me understand how Docker Compose can make cloud deployment easier and more organized, instead of manually typing several Docker commands to create and connect each container, I could write the configuration in a `docker-compose.yml` file. This file works like a blueprint for the application, so the services can be created and started together using one command. This can save time and reduce mistakes when deploying applications with multiple containers. I also learned that YAML is very sensitive to indentation. If I use a Tab instead of the required spaces or put the wrong number of spaces before a line. Docker Compose may not be able to read the file correctly. I experienced YAML errors during this laboratory, which helped me understand why proper formatting is important when writing configuration files. Environment variables such as `MYSQL_PASSWORD`, `MYSQL_DATABASE`, and `MYSQL_USER` were used to provide configuration information to the containers. They allow the Nextcloud application and MariaDB database to use the correct settings without placing these values directly into the application code. They also make the configuration easier to change when needed. Deploying Nextcloud made me feel more confident because I was able to run a real cloud storage application using containers in only a few minutes. Seeing the Nextcloud setup page in the browser showed me how the different parts of the system worked together. My understanding of Cloud Computing has developed from learning basic cloud concepts to actually deploying and managing cloud infrastructure. I have learned about Linux, cloud services, virtualization, containers, storage, and now multi-container applications. This laboratory showed me that cloud computing is not only about using cloud services but also about understanding how applications and infrastructure can be deployed and managed efficiently.
